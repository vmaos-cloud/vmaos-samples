# WebRTC 群控使用指南

本教程帮助你在浏览器中操作多台云机：左侧显示并操控一台主控云机，右侧查看其他云机的预览，并选择哪些云机跟随主控操作。

**已经建立群控，只想换一台云机作为主控时：找到右侧目标云机，点击编号后面的“操控 ▾”，选择“设为主控”。无需重新查询云机，也无需重新选择整组云机。** 详细步骤见[切换主控](#切换主控)。

> 页面中的 AK/SK 输入仅供本人电脑上的本机调试。正式业务系统应将 AK/SK 保存在后端，由后端调用接口，不应把这份带有凭据输入框的示例直接开放给其他用户。

## 先准备可直接调用的示例方法

下面每节同时提供页面操作和对应代码。代码中的 `P1`、`P2`、`P3` 都是占位编号，请换成你查询到的实际 `phoneCode`，不是列表行号。

本教程已在 [public/main.js](public/main.js) 中导出 **`groupControls`**。页面按钮和以下示例使用同一套逻辑，复制教程后即可调用，不需要自己再次拼装连接流程。

- `groupControls.switchPrimary()`、`addMembers()`、`setParticipating()` 等是**本教程提供的封装**，不是 npm SDK 的原生方法。
- `WebRtcSdk.goHome()`、`click()`、`swipe()`、`startCamera()` 等才是 **SDK 的原生方法**。教程封装会把适合群控的输入同步给当前参与的从控。
- 不要自行给 SDK 臆造 `setMainPhone()`、`addGroupMember()` 等不存在的方法，也不要新建多个 `WebRtcSdk` 实例来代替切换主控。

### 在已经打开的教程页面试用

打开教程页面的浏览器开发者工具，在控制台先执行一次：

```js
var groupControls = (await import('/main.js')).groupControls;
```

然后执行下文各功能的代码块。该入口依赖本教程的 HTML 和已加载的 SDK；请在运行中的教程页面调用，不要在 Node.js 终端或其他空白页面直接导入 `main.js`。

### 接入自己的按钮

在本教程的 `public/` 下新建一个模块，例如 `customer-controls.js`，并在页面中加载它。下面是一个完整的“切换到指定主控”按钮示例：

```html
<button id="switch-to-p2" type="button">将 P2 设为主控</button>
<p id="custom-control-status" role="status"></p>
<script type="module" src="/customer-controls.js"></script>
```

`public/customer-controls.js` 的内容：

```js
import { groupControls } from './main.js';

const button = document.getElementById('switch-to-p2');
const status = document.getElementById('custom-control-status');
button.addEventListener('click', async () => {
  button.disabled = true;
  status.textContent = '正在切换主控';
  try {
    await groupControls.switchPrimary('P2'); // P2 必须已经在当前群控名单中。
    await groupControls.waitUntilReady({ timeoutMs: 15000 });
    status.textContent = 'P2 已连接，可以继续操作';
  } catch (error) {
    status.textContent = error.message;
  } finally {
    button.disabled = false;
  }
});
```

**连接方法的 Promise 完成，只表示本轮连接初始化已完成，不等于媒体与全部从控已就绪。** 后续要批量操作时，再调用 `waitUntilReady()`。它等待主控已连接，并等待当前需要同步的从控全部就绪；超时会抛出错误，不会替你断开或重新创建整组群控。它也不代表某次点击已被云机应用执行，或预览图片已经刷新。

`getState()` 返回可读取的状态快照：当前主控、成员、同步开关、已加载云机、就绪数量等；不包含 AK/SK 或连接票据。

```js
const state = groupControls.getState();
// state.primaryCode：当前主控编号。
// state.members：{ phoneCode, primary, participating } 数组。
// state.primaryConnected：主控是否已连接。
// state.followerReadyCount / followerExpectedCount：从控就绪数 / 需要同步的从控数。
// state.ready：主控及当前所需从控是否均已就绪。
// state.availablePhones：本页已经查询加载的云机。
// state.hasMore：是否还有下一批云机可以加载。
```

## 按需要找到操作

| 你想做什么 | 应该使用的入口 | 操作结果 |
| --- | --- | --- |
| 第一次建立群控 | “连接并查询云机” → 勾选云机 → “群控所选云机” | 建立一组新的控制连接 |
| 从云机 1 切换到云机 2 操作 | 云机 2 的“操控 ▾” → “设为主控” | 保留成员名单，改由云机 2 显示在左侧 |
| 暂时只操作左侧主控 | 取消顶部“同步操作” | 从控停止接收同步操作，仍保留在群控中 |
| 暂时让某台从控不跟随 | 该从控的“操控 ▾” → 取消“参与同步” | 该机仍显示预览，但不再接收同步操作 |
| 将新云机加入当前群控 | 顶部“新增云机” | 新成员默认参与同步，不需要重建整组名单 |
| 将某台云机移出当前群控 | 该机的“操控 ▾” → “移除” | 只移出本次群控，不删除云机，也不关闭云机 |
| 左侧主控连接失败 | 顶部“重试主控” | 重新连接当前主控 |
| 主控正常，但从控控制未就绪 | 先检查同步开关，再点击“重试从控” | 重新建立参与同步的从控控制连接 |
| 只有预览图不更新 | 顶部“重新获取预览” | 重新获取图片预览授权，不重连主控视频 |
| 暂停整个群控，稍后继续 | “断开群控”，之后点击同一位置的“重新连接” | 保留当前成员、主控选择和同步设置 |
| 结束使用并清除凭据 | “退出并清除凭据” | 断开连接，清空本页凭据和成员，并退出调试会话 |

**顶部的“重新查询”会结束当前群控，返回云机选择列表。** 它适合重新挑选一整组云机，不是切换主控、添加成员或修复单一路连接的入口。

## 首次运行

### 准备条件

- 在自己的电脑上安装 Node.js **24.15.0 或更高版本**、pnpm **12.4.1**。
- 准备服务商提供的 OpenAPI HTTPS 根地址，以及有权操作目标云机的 AK/SK。
- 云机已经启动，且处于“运行中”“在线”状态。
- 使用支持 WebRTC 的浏览器，并允许本机访问服务商提供的连接与预览地址。

本教程使用公开 npm 包 `@vmaos/webrtc-sdk@0.3.2`。接口与信令服务需要支持该 SDK 使用的连接能力；请使用服务商提供的实际地址，示例域名不能直接用于连接云机。

### 配置并启动

在下载的教程仓库中，进入 `webrtc-sdk-group-samples` 目录：

```bash
cd webrtc-sdk-group-samples
```

复制配置模板。macOS/Linux 使用：

```bash
cp .env.example .env
```

Windows PowerShell 使用：

```powershell
Copy-Item .env.example .env
```

用文本编辑器打开 `.env`，填写自己的 OpenAPI HTTPS 根地址，例如：

```dotenv
OPENAPI_BASE_URL=https://openapi.example.com
PORT=5176
```

这里只填写服务地址和本地端口，**不填写 AK/SK**。然后在同一目录执行：

```bash
pnpm install
pnpm start
```

保持终端运行，在浏览器打开 **http://127.0.0.1:5176**。若修改了 `PORT`，浏览器中也使用相同端口。修改 `.env` 后，需要停止并重新启动本地服务。

SDK 会从安装的 npm 包加载，不需要另外下载 SDK 源码或配置 CDN。首次安装需要网络；如端口被占用，可在 `.env` 中换一个本地端口后重新启动。

## 建立第一组群控

1. 在页面顶部输入自己的 **AK** 和 **SK**，点击“连接并查询云机”。
2. 等待列表加载，检查每台云机的编号、运行状态与在线状态。
3. 如果目标云机不在当前列表中，点击“加载更多”。建议先加载完需要的云机，再开始勾选：**当前版本在加载更多或重新查询列表后会清空列表勾选，需要重新勾选。**
4. 勾选 **2 至 100 台**在线运行的云机，点击“群控所选云机”。不可选择的云机需要先恢复为在线运行状态。
5. 左侧初始主控是已勾选成员中**按列表顺序排在最前的一台**，不以鼠标勾选的先后决定。需要换主控时，使用右侧的“操控 ▾ → 设为主控”。
6. 等待左侧显示“已连接”。如果需要同步操作，还要等待“从控控制就绪 x / y 台”中的 `x` 与 `y` 相等，再开始批量操作。

例如，选择云机 1、2、3，云机 1 成为主控：左侧显示云机 1 的视频，右侧云机 1 的卡片显示“操控中”，云机 2、3 显示图片预览。两台从控均参与同步且控制连接就绪时，应显示“从控控制就绪 2 / 2 台”。

本页首次打开时，“同步操作”默认开启，建立群控时各成员默认参与同步。如果此前手动关闭过顶部开关，重新建立群控前也要检查其当前状态。

### 对应代码：查询并首次建立群控

先在顶部表单填写 AK/SK，再调用以下方法；不要在代码中写入真实凭据：

```js
const form = document.getElementById('login');
await groupControls.connectAndQuery(Object.fromEntries(new FormData(form)));

// 如有需要，继续加载下一批。只有已经查询到的编号才可用于 start/addMembers。
if (groupControls.getState().hasMore) await groupControls.loadMorePhones();

await groupControls.start(['P1', 'P2', 'P3']);
await groupControls.waitUntilReady({ timeoutMs: 15000 });
```

`connectAndQuery({ accessKey, secretKey })` 创建本地调试会话并重新查询，**会结束当前群控**。`start(phoneCodes)` 用指定成员建立新群控，第一项成为主控；页面勾选后调用它时，传入顺序是列表顺序。首次建立仍要求 2 至 100 台。日常换主控请调用下一节的 `switchPrimary()`，不要再调用 `start()`。

## 认识群控页面

| 位置 | 显示内容 | 如何使用 |
| --- | --- | --- |
| 左侧主控区域 | 当前主控编号、连接状态、视频和导航按钮 | 点击、拖动、输入文字、滚动，都在这里操作 |
| 右侧成员卡片顶部 | “主控/从控”标签、完整云机编号、“操控 ▾”菜单 | 按编号找到目标，在菜单中调整角色、参与同步状态或移除成员 |
| 右侧当前主控卡片 | 居中显示“操控中” | 表示该机已在左侧操控，不会重复显示一份视频 |
| 右侧从控卡片 | 定期更新的云机截图 | 用于查看结果；**直接点击截图不会操控该从控** |
| 顶部工具栏 | 同步开关、成员添加、分项重试、断开与退出 | 按具体需要选择对应入口 |

右侧列表可以单独上下滚动，左侧主控不会跟随列表滚走。预览区高 480px，图片等比例显示；不同屏幕比例出现黑边属于完整显示的正常结果。

从控图片不是连续视频。滚动到可见位置后才会更新；切换到其他浏览器标签页时会暂停拉图，返回后恢复。因此，预览图可能比实际操作稍晚，不代表控制一定失败。完成关键操作后，应等待预览刷新，再检查结果。

“从控控制就绪 x / y 台”只统计当前需要参与同步的从控控制连接，不统计主控，也不统计取消参与同步的成员。关闭全局同步、没有参与同步的从控或只剩一台主控时，可能显示“从控控制未连接”；在这些情况下无需为了该提示反复重试。

## 切换主控

### 示例：让云机 2 接替云机 1

当前云机 1、2、3 已在同一组内，只需要改为直接操作云机 2：

1. 先结束正在进行的拖动或文字输入。
2. 在**右侧找到云机 2 的编号**，不要在云机 1 的菜单中操作。
3. 点击云机 2 编号后的 **“操控 ▾”**。
4. 选择 **“设为主控”**。
5. 等待左侧主控编号变为云机 2，并显示“已连接”。右侧云机 2 会变为“主控”标签和“操控中”占位，云机 1 则恢复为从控预览。
6. 需要继续同步操作时，再确认从控控制就绪数量达到预期。

**这一步保留原来的成员名单和全局同步开关，不需要重新输入 AK/SK、不需要点击“重新查询”，也不需要再次“群控所选云机”。** 右侧成员的顺序也保持不变，方便继续按编号查找。

### 对应代码：切换到已有成员

前提：群控已经建立，P2 已经在当前成员名单中。

<!-- example: switch-primary -->
```js
await groupControls.switchPrimary('P2');
await groupControls.waitUntilReady({ timeoutMs: 15000 });
```

调用后仍是原来那一组成员，只把 P2 设为主控。对已经是主控的 P2 再次调用，会直接返回，不会再次建立连接。目标不在当前名单时会抛出错误；先用 `addMembers()` 加入，不要通过 `start()` 重建名单来切换。

这两个方法分别执行“切换”和“等待就绪”，没有调用 `connectAndQuery()`、`reloadPhones()` 或 `start()`。如果当前整组已经断开，先调用 `reconnect()` 并等待就绪，再切换。

### 切换时需要等待什么

当前教程会在切换时释放旧主控连接，为新主控建立视频连接，并重新建立从控控制连接、加载预览。期间可能出现短暂黑屏、预览重新加载或控制暂未就绪；这不是让你再次重建群控的提示。请等待状态恢复后再操作，避免反复点击切换或连接按钮。

此切换入口用于避免重新挑选整组云机，但**并不保证切换过程中所有云机都完全没有闪屏或停顿**。如果一直无法连接，按[连接异常时如何恢复](#连接异常时如何恢复)处理具体故障。

### “设为主控”不可点击时

- 该卡片已经是主控：不需要再设置一次。
- 整组已经断开：先点击顶部“重新连接”，再切换主控。
- 打开菜单找错了卡片：核对目标云机编号，点击的是目标卡片自己的“操控 ▾”。

## 调整同步范围

同步操作是把鼠标、键盘、文字、滚轮和导航操作发送给参与的云机，**不是把主控的画面、应用或数据复制给从控**。相同点击落在不同应用页面上，可能得到不同结果；批量操作前，应尽量让各台云机处于相同应用、页面和屏幕方向。

### 全局开关：只操作主控或恢复群控

- 取消顶部“同步操作”：后续输入只作用于左侧主控。右侧成员与预览仍保留，各成员的“参与同步”设置也保留。
- 重新勾选“同步操作”：恢复对已开启“参与同步”的从控下发操作。等待从控控制重新就绪后再操作。

对应代码：

<!-- example: sync-off -->
```js
await groupControls.setSynchronous(false); // 后续输入仅作用于当前主控。
```

恢复时：

```js
await groupControls.setSynchronous(true);
await groupControls.waitUntilReady();
```

`setSynchronous(enabled)` 的参数是布尔值，负责更新全局开关与从控控制连接，不创建新的主控视频实例。

### 单台开关：暂时排除某台从控

1. 找到该从控的“操控 ▾”菜单。
2. 查看“参与同步”前的勾选标记：有勾表示已开启，无勾表示未开启。
3. 点击“参与同步”切换状态。
4. 需要重新纳入时，在同一菜单中再次开启。

取消“参与同步”后，该机仍是群控成员，仍显示预览，之后随时可以恢复；它与“移除”不同。主控始终接收本页操作，不能通过自己的“参与同步”菜单关闭主控输入。

要让一台从控接收到操作，需要同时满足：顶部“同步操作”开启、该机“参与同步”开启、该机控制连接已就绪。**控制未就绪时的操作不会缓存，也不会在连接恢复后自动补发。**

对应代码：假设 P3 是从控。

<!-- example: exclude-member -->
```js
await groupControls.setParticipating('P3', false);
await groupControls.waitUntilReady();
```

恢复 P3：

```js
await groupControls.setParticipating('P3', true);
await groupControls.waitUntilReady();
```

`setParticipating(phoneCode, enabled)` 只改变这台成员的同步选择，保留成员名单；实际从控控制连接会按新的范围重建。不能将当前主控设置为 `false`。如果只是想只操作主控，使用 `setSynchronous(false)`。

### 只调整云机 2，不影响云机 1、3

1. 取消顶部“同步操作”。
2. 在云机 2 的“操控 ▾”菜单选择“设为主控”。
3. 等待云机 2 连接成功，再把它调整到需要的页面。
4. 按需要切回合适的主控，核对其他成员的“参与同步”状态。
5. 重新开启顶部“同步操作”，等待从控就绪，再恢复批量操作。

仅取消云机 2 的“参与同步”，不会让它的截图变成可操作窗口。要直接操作它，仍需要把它设为主控。

对应代码：先关闭同步，再切到 P2 操作。

```js
await groupControls.setSynchronous(false);
await groupControls.switchPrimary('P2');
await groupControls.waitUntilReady();
groupControls.home(); // 这次 Home 只发送给 P2。
```

调整完成并确认各台页面适合继续同步后，再调用 `setSynchronous(true)` 并等待就绪。不要在尚未确认各台状态时自动恢复批量输入。

## 在当前群控中新增云机

例如原有云机 1、2，想把云机 3 加进来：

1. 点击顶部“新增云机”，打开“新增群控云机”对话框。
2. 等待候选云机加载。找不到目标时，点击对话框内的“加载更多”；也可以输入编号，**筛选已经加载的候选项**。筛选框不会自动到服务器查找尚未加载的云机。
3. 勾选云机 3，检查已选数量，再点击“加入群控”。
4. 云机 3 会追加到右侧列表末尾，并默认开启“参与同步”。原主控保持不变。
5. 顶部全局同步开启时，等待新成员及其他需要同步的从控重新就绪后，再继续操作。

已有成员显示“已在群控中”，不能重复加入。只有在线且运行中的云机可以加入；含主控在内最多 100 台，取消某台的“参与同步”不会释放成员名额。

对话框中的“取消”或 `Esc` 会放弃本次新增。对话框内的“重新查询”只刷新候选列表，并清空本次候选勾选；**它不会退出当前群控**，与页面顶部的“重新查询”作用不同。

整组断开后仍可新增成员，名单会先更新；点击“重新连接”后才建立控制连接。整组已经有 100 台时，“新增云机”不可点击，需要先移除部分成员。

### 对应代码：向现有群控追加成员

前提：P3 已经出现在本页查询结果或“新增云机”对话框加载过的候选项中，且在线运行；当前群控可以只包含 P1、P2。

<!-- example: add-member -->
```js
await groupControls.addMembers(['P3']);
await groupControls.waitUntilReady();
```

`addMembers(phoneCodes)` 接收编号数组；它从教程已加载的候选数据中找到目标，追加到名单并默认参与同步。当前主控不变。重复加入已有成员不会重复建连接；超出 100 台、目标未加载或未在线运行时会抛出错误，调用前不会先破坏当前名单。

如目标未加载，可先检查 `getState().hasMore` 并调用 `loadMorePhones()`；该方法继续查询，不会清空当前群控。不要使用会结束群控的 `reloadPhones()` 来完成常规追加。

## 移除群控成员

1. 找到目标云机卡片，核对完整编号。
2. 点击“操控 ▾” → “移除”。
3. 该卡片从当前群控中消失，之后不再接收本组同步操作或刷新本页预览。

“移除”只改变本页群控名单，**不删除云机、不关机、不卸载应用**。如果移除的是当前主控，教程会自动将剩余名单中的第一台设为新主控；不希望自动选择时，可先把你指定的另一台“设为主控”，再移除原来的主控。

至少保留一台云机，最后一台的“移除”不可点击。由多台减少到一台后，仍可以继续操作、断开后重新连接，也可以再次新增成员。

如果只是暂时不希望某台跟随，应取消它的“参与同步”；移除后想重新加入，需要再次通过“新增云机”选择它。

### 对应代码：移除指定成员

<!-- example: remove-member -->
```js
await groupControls.removeMember('P3');
await groupControls.waitUntilReady();
```

`removeMember(phoneCode)` 接收当前成员的编号，不调用云机删除或关机接口。移除主控会按剩余名单选定新主控；移除最后一台或传入不存在的成员会抛出错误。

如果希望移除 P1 前明确指定 P2 接任，可调用：

```js
await groupControls.switchPrimary('P2');
await groupControls.waitUntilReady();
await groupControls.removeMember('P1');
await groupControls.waitUntilReady();
```

## 操作主控与同步输入

| 功能 | 客户如何操作 | 作用范围与使用提示 |
| --- | --- | --- |

| 粘贴本机文字 | 复制本机纯文本，点击主控中的目标输入框，再使用 `Ctrl+V`，macOS 使用 `Command+V` | 发送纯文本，不提供文件、图片粘贴或文件上传功能 |
| 功能键 | 主控画面获得输入焦点后，使用 Enter、退格等支持的按键 | 按键只在当前画面接收键盘输入时发送 |

| 鼠标滚轮 | 将鼠标放在主控画面内滚动滚轮 | 同步滚动输入；滚动结果取决于各云机当前页面是否支持滚动 |

鼠标移出主控区域、切到其他窗口、修改同步范围或断开时，页面会结束当前输入或触控；需要继续输入时，重新点击主控中的目标输入框。不要一边拖动，一边切换主控或调整成员。

本群控页面保持静音，不提供声音或音量调节按钮。没有声音不代表视频或同步操作失效。

“操控 ▾”菜单也支持键盘：聚焦菜单入口后，使用 Enter 打开；上下方向键选择项目，Enter 执行，`Esc` 关闭。

### 对应代码：导航、坐标操作、文字与按键

先确认主控和需要参与的从控已经就绪，以及各台当前页面允许执行这些操作。

<!-- example: navigation -->
```js
await groupControls.waitUntilReady();
groupControls.home();        // 底层调用当前主控 SDK 的 goHome()。
groupControls.back();        // 底层调用 goBack()。
groupControls.recentTasks(); // 底层调用 goTask()。
```

坐标采用当前云机画面的 **0–1 比例**，左上角 `(0, 0)`，右下角 `(1, 1)`。以下值不是 CSS 像素；持续时间参数的单位是毫秒。

<!-- example: gestures -->
```js
await groupControls.waitUntilReady();
await groupControls.click(0.5, 0.5);
await groupControls.swipe(0.5, 0.8, 0.5, 0.2, { durationMs: 300 });
await groupControls.drag(0.2, 0.5, 0.8, 0.5, { holdMs: 500, durationMs: 600 });
groupControls.scroll(120); // 正值/负值表示两个滚动方向，不保证滚动相同像素距离。
```

这些方法分别调用当前 SDK 的 `click()`、`swipe()`、`drag()`、`scroll()`；教程适配器会同步已接受的输入。多个动作请顺序 `await`，不要一边调用编程拖动，一边在画面手动拖动。Promise 完成表示动作发送流程完成，不是云机应用的执行回执。

点击各台的目标输入框后，发送纯文本或 Android 按键码：

<!-- example: text-and-key -->
```js
await groupControls.waitUntilReady();
groupControls.sendText('你好，群控示例');
groupControls.sendKey(66); // Android KEYCODE_ENTER；可选第二参数 meta 默认为 0。
```

`sendText(text)` 和 `sendKey(keyCode, meta)` 是教程封装，不是 `WebRtcSdk` 的原生同名方法。底层经公开的 `WebRtcClient.sendChannelData()`，分别发送 `ActionChinese + InputData`、`ActionInput + KeyEventData`；仍经过当前连接与同步范围判断。文字须为非空字符串，按键码与 `meta` 须为非负整数。

不要仅创建一个全新的 `WebRtcClient` 来发送文字，那样会绕开当前群控的连接与同步管理。发送前由接入方确认当前云机应用与输入框；本教程不提供“输入框已接收文字”的回执。

## 将主控中的文字复制到本机

此功能处理**云机复制 → 本机粘贴**，与前面的“本机文字 → 云机输入”方向相反：

1. 在当前主控的应用中选择文字，执行该应用的“复制”。
2. 浏览器允许自动写入本机剪贴板时，可以直接在本机应用粘贴，不会额外弹出提示。
3. 如果顶部出现“云机文字待复制”，点击“复制到本机”，再到本机应用粘贴。
4. 如果仍不能复制，点击“查看文字”，在展开的文字框中选中需要的文字，手工复制；“收起文字”可隐藏文字框。
5. 不再需要该提示时，点击“关闭”。之后重新在云机中复制文字，仍可以产生新的提示。

浏览器权限、页面是否有焦点、是否处于安全上下文都会影响自动复制。请优先使用教程默认的本机访问地址；自动复制失败时，使用提示中的手动方式即可，不需要重建群控。

只接收**当前主控**的复制文字，不读取从控剪贴板，也不会自动把收到的文字粘贴到其他云机。切换主控、重试主控、断开或退出后，旧连接的复制提示会清除。

### 对应代码：剪贴板监听已经由教程挂载

当前教程在 `createControlledSdk()` 的公开 `clientFactory` 回调里，为当前主控调用了以下辅助函数。正常使用 `groupControls` 时已自动完成，**不要再挂载一次**。

```js
import { mountCloudClipboard } from './clipboard.js';

// 仅在你自己实现 clientFactory、替换现有输入适配器时参考：
function attachClipboard(SDK, client) {
  // client 是你在 clientFactory 中创建的当前主控 WebRtcClient。
  const cleanup = mountCloudClipboard(SDK, client);
  // 将清理函数交给你的主控切换/销毁逻辑，在旧 client 销毁前调用。
  return cleanup;
}
```

该函数监听 SDK 公开事件 `EmitType.cloudClipData`，处理自动写入本机剪贴板与手动复制提示。切换主控和退出时，教程已调用返回的清理函数；**不存在一个需要客户额外调用的“从全部云机复制”方法**。

## 将本机摄像头用于主控云机

摄像头能力由当前主控中的应用请求，本页并没有一个始终显示的“开启摄像头”按钮。使用方式是：

1. 将需要摄像头的云机设为主控，并等待“已连接”。
2. 在该云机中打开需要拍照或视频采集的应用，让应用发起摄像头使用请求。
3. 浏览器请求访问本机摄像头时，根据需要选择设备并允许授权。等待摄像头区域从“等待摄像头授权”变为“摄像头传输中”。
4. 传输开始后，可使用出现的“前置”“后置”按钮切换可用摄像头；实际效果取决于本机设备与浏览器支持。
5. 不再使用时点击“关闭摄像头”。如提示错误，检查浏览器站点权限、设备是否连接或被其他程序占用，再点击“重试摄像头”。

摄像头只传给当前主控，**不会随群控同步给从控**；本教程不申请麦克风。切换或重连主控、断开群控、退出时会释放本次摄像头采集，新主控需要重新触发摄像头使用。

摄像头授权失败时，主控桌面控制可以继续使用。仅摄像头有问题时，使用“重试摄像头”，不要因此点击“重试主控”或重新建立整组群控。

### 对应代码：摄像头控制

云机应用已经请求使用摄像头、主控连接正常后，可以在自己的按钮点击处理函数中调用：

```js
await groupControls.startCamera();
await groupControls.switchCamera({ useBackCamera: true });  // 后置。
await groupControls.switchCamera({ useBackCamera: false }); // 前置。
groupControls.stopCamera();
```

它们分别调用 SDK 的 `startCamera()`、`switchCamera()`、`stopCamera()`。`startCamera()` 的可选参数也接受 `{ useBackCamera: true }`；首次采集需要浏览器权限与可用设备。需要等待的摄像头方法应使用 `await` 并通过 `try/catch` 展示错误，不要在页面加载时无提示地连续申请权限。

摄像头只作用于当前主控，不进入从控输入广播。摄像头事件与错误提示由 `mountCameraControls()` 挂载，默认教程已经处理；不需要为了关闭摄像头调用 `disconnect()`。

## 连接异常时如何恢复

先看清是主控、从控控制还是预览出了问题，再使用对应入口。**能看到截图不代表从控控制已经就绪；截图不更新也不代表主控连接一定断开。**

| 现象 | 先检查 | 推荐操作 |
| --- | --- | --- |
| 左侧显示“连接失败，请重试主控”，或左侧视频连接异常 | 该云机是否在线运行、本机网络是否正常 | 当前群控仍处于连接状态时点击“重试主控”，等待“已连接” |
| 主控可以操作，但部分从控没有跟随 | 顶部“同步操作”、目标的“参与同步”、从控就绪数量 | 开关正确时点击“重试从控”，等待就绪后再继续 |
| 只有右侧图片停留在旧画面 | 卡片是否在可见区域、浏览器页面是否在前台 | 先滚动到目标并返回页面；仍不更新时点击“重新获取预览” |
| 显示“等待截图” | 云机是否在线，截图服务是否已产生画面 | 稍等后观察；持续无图时联系服务商检查预览服务，不必反复重建群控 |
| 显示“预览授权已失效，等待续期”或“正在重试预览” | 网络及页面是否已回到前台 | 教程会尝试恢复；需要立即重取授权时点击“重新获取预览” |
| 画面正常，但文字没有进入云机 | 是否点击了云机中的输入框、鼠标是否仍在主控区域 | 重新点击目标输入框后输入；不要把右侧截图当成输入窗口 |
| “设为主控”不可点击 | 目标是否已是主控，整组是否已断开 | 已是主控无需操作；已断开先点“重新连接” |
| 页面提示“请重新输入 AK/SK” | 调试会话是否过期、本地服务是否重启 | 重新输入 AK/SK，点击“连接并查询云机”，重新选择并建立群控 |
| 所有接口持续失败 | `.env` 地址、本机服务终端与网络 | 核对服务地址，按页面错误处理；仍失败时记录发生步骤和现象交给服务商 |

本地调试会话最长 30 分钟，到期后查询、申请连接或预览授权等操作需要重新登录。会话过期和日常切换主控是两种不同情况，不要把重新登录当作每次切换的固定步骤。

“重试主控”“重试从控”“重新获取预览”不会把已经由你明确“断开”的整组自动重新接通。已点击“断开群控”时，使用同一位置显示的“重新连接”。

### 对应代码：按故障类型重试

主控连接失败：

<!-- example: retry-primary -->
```js
await groupControls.retryPrimary();
await groupControls.waitUntilReady();
```

主控正常、从控控制未就绪：

<!-- example: retry-followers -->
```js
await groupControls.retryFollowers();
await groupControls.waitUntilReady();
```

仅图片预览异常：

<!-- example: refresh-previews -->
```js
await groupControls.refreshPreviews();
```

这三个入口分别封装当前教程的 `rebuildMain()`、`rebuildFollowers()`、`grantPreviews()`。`refreshPreviews()` 完成后仍要等待图片下载显示；`waitUntilReady()` 检查的是控制连接，不检查图片，也不应被当作图片成功的回执。

整组已经明确断开时，上述重试入口会报错，请按下文使用 `reconnect()`。

### 各项操作会影响哪些连接

| 操作 | 左侧主控视频 | 从控控制连接 | 右侧从控预览与成员名单 |
| --- | --- | --- | --- |
| 开关顶部“同步操作” | 保留 | 按开关关闭或重新建立 | 预览与名单保留 |
| 开关某台“参与同步” | 保留 | 按新的同步范围重新建立 | 预览重新加载，名单保留 |
| 新增成员、移除非主控成员 | 保留 | 按新的成员范围重新建立 | 预览重新加载，名单更新 |
| “设为主控”、移除当前主控 | 切换到新的主控连接 | 重新建立 | 预览重新加载，已有成员顺序保留；移除时只删对应成员 |
| “重试主控” | 重新建立当前主控连接 | 保留 | 预览与名单保留 |
| “重试从控” | 保留 | 重新建立 | 预览与名单保留 |
| “重新获取预览” | 保留 | 保留 | 重新获取预览授权，名单保留 |
| “断开群控”后“重新连接” | 先关闭，再重新建立 | 先关闭，再按同步设置建立 | 先停止，再恢复；名单保留 |
| 顶部“重新查询”或再次“连接并查询云机” | 结束当前群控 | 结束当前群控 | 返回选择列表，需重新选择成员 |

涉及连接或预览重建的操作都可能带来短暂等待。看到从控就绪数量暂时下降时，请等待重新就绪，不要连续发送一批操作指望它们稍后补发。

## 暂停、退出与重新选择整组云机

### 暂时停用，稍后继续

点击“断开群控”，等待连接停止。按钮会变为“重新连接”，当前成员、主控和同步设置保留。再次点击“重新连接”，等待主控与需要同步的从控就绪后继续。

这只结束本页控制与预览，不会向云机发送关机或重启命令。断开期间仍可以新增或移除成员，但不能直接切换主控；移除当前主控会先在名单中选定新的主控，重连时再连接它。

对应代码：

<!-- example: disconnect-reconnect -->
```js
groupControls.disconnect(); // 停止本组连接与预览，保留成员和同步选择。
await groupControls.reconnect();
await groupControls.waitUntilReady();
```

`disconnect()` 可重复调用；`reconnect()` 在已经连接中的群控上不会再次重建一整组连接。它用于恢复已断开的现有名单，不替代首次调用 `start()`。

### 结束本次使用

1. 点击“退出并清除凭据”，清除 AK/SK 输入、当前名单与本页连接，并退出服务端调试会话。
2. 不再使用本地教程服务时，再到启动它的终端按 `Ctrl+C`。

刷新或关闭浏览器页面也会停止当前页面的控制，但不会替你保存群控名单。**成员、主控与同步设置只保存在当前页面内存中；刷新后需重新输入 AK/SK、查询和选择成员。** 想稍后按原名单继续，应使用“断开群控”，保留页面，不要刷新代替暂停。

对应代码：

```js
await groupControls.logout();
```

`logout()` 清空本页连接、成员、输入凭据并请求退出本地调试会话；再次使用时调用 `connectAndQuery()`，重新查询和建立群控。单纯切换主控不要调用它。

### 确实需要重新选择一整组

使用顶部“重新查询”，返回选择列表，按需“加载更多”，再勾选 2 至 100 台云机，点击“群控所选云机”。如果只是换主控、增减成员或排除某台的同步，优先使用前面的专用入口。

对应代码：只有你确实需要重新选择整组时才执行。

```js
await groupControls.reloadPhones(); // 结束当前群控，重新查询；此后没有活动成员。
// 从 getState().availablePhones 中选择新的一组，再调用 start([...])。
```

### 方法与作用范围速查

| 功能 | 教程中可实际调用的方法 | 重要参数或前提 |
| --- | --- | --- |
| 登录并查询 | `connectAndQuery({ accessKey, secretKey })` | 从表单读取凭据；会结束现有群控 |
| 查询下一批 | `loadMorePhones()` | 先看 `getState().hasMore`；保留当前活动群控 |
| 重新查询整组 | `reloadPhones()` | 会结束当前群控 |
| 首次建立 | `start(phoneCodes)` | 2–100 个已加载且在线运行的编号；第一项为主控 |
| 切换主控 | `switchPrimary(phoneCode)` | 目标必须在当前活动名单中；保留名单 |
| 开关全局同步 | `setSynchronous(enabled)` | 布尔值 |
| 开关单台参与 | `setParticipating(phoneCode, enabled)` | 从控编号与布尔值 |
| 追加成员 | `addMembers(phoneCodes)` | 已加载的编号数组；已有成员自动忽略 |
| 移除成员 | `removeMember(phoneCode)` | 至少保留一台；移除主控会自动选定新主控 |
| 导航 | `home()` / `back()` / `recentTasks()` | 主控已连接；按当前范围同步 |
| 点击/滑动/拖动 | `click()` / `swipe()` / `drag()` | 0–1 坐标；动作顺序 await |
| 滚轮 | `scroll(deltaY)` | 有限非零数值，正负表示方向 |
| 文字/按键 | `sendText(text)` / `sendKey(keyCode, meta)` | 主控已连接，应用输入框由调用方确认 |
| 摄像头 | `startCamera(options?)` / `switchCamera(options)` / `stopCamera()` | 仅主控；`useBackCamera` 为布尔值 |
| 分项恢复 | `retryPrimary()` / `retryFollowers()` / `refreshPreviews()` | 群控仍为活动状态 |
| 暂停/继续 | `disconnect()` / `reconnect()` | 保留当前成员与同步设置 |
| 清除会话 | `logout()` | 结束本次使用，之后需重新登录查询 |
| 状态/等待 | `getState()` / `waitUntilReady({ timeoutMs })` | 超时为正数毫秒，默认 15000；不代表业务执行或图片已刷新 |

上述均指 `groupControls` 的成员；与 SDK 原生方法的对应关系已在各节代码旁说明。

## 给接入开发者的说明

本示例只依赖公开 npm SDK 和公开接口。浏览器通过本地示例后端完成查询与授权，AK/SK 签名在后端执行。当前页面主要使用：

| 公开接口 | 本教程中的用途 |
| --- | --- |
| `POST /open-api/phone/query` | 获取当前凭据可访问的云机；通过“加载更多”继续读取 |
| `POST /open-api/phone/connection-ticket` | 为主控、参与同步的从控分别获取一次性连接凭证；连接重建时重新申请 |
| `POST /open-api/phone/screenshot-token` | 获取和续期各成员的图片预览授权 |

示例后端还保留 `/api/group-ticket` 到 `POST /open-api/phone/group-connection-ticket` 的映射，便于接入者使用批量授权；**当前教程页面实际通过 `/api/ticket` 为各台云机分别申请凭证**，不是调用批量接口后再次创建一组独立群控。

将教程接入正式产品时，保留登录用户与可操作云机的权限校验，把 AK/SK 放在自己的后端，并按自己的业务提供鉴权入口。不要将当前本机凭据输入页面直接当作面向公众的登录系统。

页面由 `public/main.js` 组织群控，`public/members.js` 提供成员操控菜单，`public/control.js` 负责输入与同步适配，`public/preview.js` 负责预览，`public/camera.js`、`public/clipboard.js` 分别提供摄像头与云机复制文字提示。复制或调整示例时保留这些配套文件，通过 npm 使用对应 SDK，不需要复制 SDK 源码或本地生成的 SDK 文件。

`.env`、`node_modules/`、`dist/` 和运行时生成的 SDK 文件不应提交。凭据、连接票据与预览地址也不要写入日志、导航 URL 或浏览器持久存储。页面退出会清理本例的服务端会话；后端不会将 AK/SK 写入 `.env` 或 Cookie。
